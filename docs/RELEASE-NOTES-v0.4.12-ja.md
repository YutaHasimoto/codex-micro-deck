# Codex Shortcuts Plugin v0.4.12 リリースノート

## 右下の専用Voiceキー

既定プロファイルの右下キーをDeclineからVoiceへ変更しました。1回押すとCodexの音声入力を開始し、キーを離しても録音を継続します。もう一度Voiceキーを押すと、Codex自身の「文字起こしして送信する」を実行します。

録音していないときは白いマイクと`Tap to talk`、録音中は青いマイクと`Listening…`を表示します。4つのダイヤル画面には従来どおり、録音中の全幅波形を表示します。

## 重複イベントを安全に無視

Stream Deckから同じ物理押下のdownイベントが複数届いても、開始直後に送信へ反転しないよう、押下元を記録して2回目以降を無視します。key upでは録音状態を変えず、次の物理押下を開始／送信の切り替えとして扱います。開始と送信は既存のダイヤル音声入力と同じキューで直列処理します。

## 既存キー役割との互換性

Decline役割は削除していません。Stream DeckのProperty Inspectorから任意キーへ割り当て直せます。

従来の`ptt`役割も「音声入力（押している間）」として維持しています。こちらはキーを押している間だけ録音し、離すと文字起こしを入力欄へ挿入します。新しいVoiceキーは「音声入力（開始／送信）」として区別して表示します。

## 権限とプライバシー

VoiceキーはCodex画面の英語／日本語アクセシビリティラベルへ完全一致して操作します。macOSのアクセシビリティ／オートメーション権限とCodex自身のマイク権限が必要です。

同梱ヘルパーは波形表示のためにRMS音量だけを計算し、音声を保存も外部送信もしません。RMS用のマイク権限がない場合でも、Codex側の録音と文字起こしは分離して動作します。

RMS用ヘルパーにマイク権限がない場合は、エラー表示にせず静かなアニメーション波形へ自動的に切り替えます。Codex自身の音声入力はそのまま継続します。

## 送信後の誤警告を修正

Codexの「文字起こしして送信する」を押した直後に画面が生成中へ切り替わると、アクセシビリティ操作は届いているのに完了応答だけが遅れ、Stream Deckがエラーを表示する場合がありました。ボタン押下の応答待ちだけを短く区切り、同じ送信を自動再試行しないよう修正しました。

## 長いタスクでの開始タイムアウトを修正

会話履歴が長いタスクでは、音声入力ボタンを探す際に会話全体のアクセシビリティ要素まで走査し、開始前にタイムアウトする場合がありました。開始時は既知の入力欄パスを直接たどり、最後の親要素の直下だけから`Dictate`／`音声入力`を完全一致で探します。再帰検索やメニューバー検索は行いません。

開始ボタンへの`AXPress`がCodex側で受理されていないのに、Stream Deckだけが`Listening…`へ進む場合がありました。開始操作はCodex内蔵の`Start dictation`／`音声入力を開始`コマンドへ変更し、入力欄に`Stop dictation`または`Transcribe and send`が実際に表示された場合だけ録音開始として扱います。確認できない場合は自動再試行せず、デッキも待機表示のままにします。

Electronの音声ボタンは表示中でもAccessibilityの`visible`属性を返さない場合があり、前段のボタン確認が誤って`control-not-found`となる問題も修正しました。音声操作は会話履歴を走査せず、入力欄の限定されたAccessibilityサブツリー内にある、有効かつ完全一致する一意のボタンだけを対象にします。プラグイン再起動後もCodex側で録音が続いている場合は、二重に開始せず状態を同期します。
