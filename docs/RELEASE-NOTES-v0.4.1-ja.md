# Codex Micro Deck v0.4.1 リリースノート

リリース日: 2026年7月24日

v0.4.1では、4つの設定ダイヤルを「現在の1タスクだけ」ではなく、Deckが追跡するAgentタスク全体へ同期する操作に変更しました。Approve／Declineは実際に応答できる承認要求がある間だけ点灯し、Approvalの通常候補からNeverを外しました。

## 新規タスクの既定値とAgentタスクを一度に同期

Model、Reasoning、Speed、Approval levelを適用またはリセットすると、次の順で処理します。

1. `~/.codex/config.toml`へ新規タスクの既定値を原子的に保存します。
2. Agent 1〜6の各論理枠を、自動割り当て、固定ID、未割り当てのいずれかとして解決します。
3. 有効なタスクIDだけを重複排除し、最大6件の同期対象を作ります。
4. 保存済みのModel、Reasoning、Speed、Approval levelを完全な1組として各タスクへ同期します。

固定枠は同じindexの自動タスクを置き換えます。直近6件と固定枠を足し合わせないため、Deckの6枠にない7件目以降へ誤同期しません。キー描画より先に設定を適用した場合も、直近タスクから作った自動割り当てをfallbackとして使います。

Agentキーを別役割へ変更したときは、変更前のroleと座標から旧Agent枠を正確に解除します。キーがページ／プロファイルから消えるときも表示中に記録した旧設定を使って解除するため、外した固定IDが後の同期対象に残りません。

1項目だけではなく4設定をまとめて送るため、以前のタスク固有設定が残ってDeck表示と実際の動作が食い違うことを防ぎます。各タスクで現在実行中のターンは途中変更せず、次のターンから新しい設定を使います。

同期処理はダイヤル操作の順序どおりに待ち行列で実行します。先の設定同期が終わる前に、後のダイヤル設定が追い越すことはありません。

現在Desktop followerがfollow中のタスクは、常設IPCのexact-ID更新で即時反映も補助します。ただしfollower成功だけでは永続化済みと数えません。その成否にかかわらず、同梱Codex CLIのApp Serverをそのbatchで1回だけ`experimentalApi`付きで起動し、全対象のexact IDへ`thread/resume`、続けて`thread/settings/update`を送ります。同期成功件数はこの永続更新の成功を基準にし、全対象の処理後は成功・失敗にかかわらずApp Serverを停止します。

## 同期件数が分かる物理表示

| Deck表示 | 意味 |
|---|---|
| `✓ Synced` | 全対象へ同期成功。補助表示は`N tasks · new default` |
| `✓ Default` | 追跡タスクが0件。新規タスクの既定値だけ保存 |
| `⚠ X/N` | 全N件中X件へ同期成功。一部または全部が失敗したため再適用が必要。全件失敗は`⚠ 0/N` |

一部失敗は`Partial sync · retry`とともに4秒間アンバー表示します。成功したタスクは巻き戻しません。再試行では失敗IDだけを保持せず、同じ完全な設定を全対象へもう一度送ります。完全設定の更新は冪等なので、既に成功したタスクへ再送しても最終状態は変わりません。

## ApprovalはStrict、Ask、Autoの3候補

通常のApprovalダイヤル候補は次の3つです。

| 表示 | 意味 |
|---|---|
| Strict | 常に確認 |
| Ask | 必要なときに確認。既定値 |
| Auto | 必要なときに自動レビュー |

旧設定のNeverは読み込みとIPC変換の後方互換だけを残し、ダイヤルを回しても候補には出ません。Never表示のままApprovalダイヤルを押した場合は、設定保存もタスク同期も行わず、Strict、Ask、Autoのどれかへ回すよう明示します。通常のModel、Reasoning、Speed操作は、読み込んだNeverを暗黙に変更しません。v0.4.1を配備する前に、一回限りの移行ツールを完了します。

```sh
node scripts/migrate-approval-ask.mjs
node scripts/migrate-approval-ask.mjs --apply
```

引数なしはdry-runです。`--apply`は新規タスクの既定値と重複のない直近6タスクについて、承認に関する2項目だけをAskへ変更します。実設定と実タスクを変更するため、dry-run結果と対象6件を確認してから実行し、成功をv0.4.1配備の必須完了条件とします。Approvalタッチ領域の長押しも従来どおりAskへ戻します。

## Approve／Declineは実承認待ちのときだけ点灯

- コマンド実行またはファイル変更の承認要求がある間だけ、Approveはアンバー、Declineは赤で点灯します。
- 質問への回答だけを待っている場合はAgentキーがアンバーでもApprove／Declineは消灯します。質問はCodex側で回答します。
- 複数タスクに実承認待ちがある場合は、明示的に選択したAgentを最優先し、未選択ならCodexで現在表示中の一意な対象を使います。
- 対象を安全に決められない場合や、同じタスクに複数の実承認要求がある場合は推測せず、Codex側での操作を案内します。
- 承認・却下は従来どおりlive requestIdを指定して送信し、キーボード入力は使いません。

消灯中のApprove／Declineを押しても承認は送信されません。

## 更新後の確認

1. Codexデスクトップを起動し、配備担当者が一回限りのNever→Ask移行を完了します。
2. Agent 1〜6へタスクが表示されるまで待ちます。
3. Model、Reasoning、Speedのいずれかを回して350ミリ秒待つか、ダイヤルを押します。
4. `✓ Synced`と同期件数が表示されることを確認します。
5. Approvalダイヤルを回し、Strict、Ask、Autoだけが循環することを確認します。
6. 実承認要求を発生させ、Approve／Declineが点灯中だけ操作できることを確認します。
