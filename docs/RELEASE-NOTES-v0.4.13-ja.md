# Codex Shortcuts Plugin v0.4.13 リリースノート

v0.4.13は、v0.4.12で追加した専用Voiceキーと4本共通のダイヤル音声入力を維持しながら、誤入力・誤送信と状態固着を防ぐために操作経路と状態管理を見直した安全性修正版です。

## 音声開始からCmd+Kを撤去

音声入力の開始にCmd+Kコマンドパレットを使用しないよう変更しました。Codexの編集メニューにある「音声入力を開始…」または`Start Dictation…`を完全一致で選びます。該当メニューを利用できない場合だけ、入力欄付近の限定されたcomposer領域から、有効かつ一意な音声入力ボタンを完全一致で探して操作します。

composer領域の探索は1回の走査で必要な属性を集めるsingle-pass方式です。Electron上で安定して取得できない`visible`属性は参照しません。会話履歴全体や無関係な画面要素を繰り返し走査せず、候補が一意でない場合は何も押さずエラーにします。

## 連打と録音中の誤操作を抑止

開始または停止処理中は、別のVoiceキーや別のダイヤルから届いた追加押下もキューへ積まず、その場で無視します。処理終了後は成功・失敗にかかわらずガードを解除し、次の物理押下を受け付けます。

録音中は、停止に必要なVoice操作を除き、カスタムショートカット、Enter、Escape、Fork、承認・却下、Agentキー、ダイヤル回転、タッチ操作を実行しません。キーがプロファイル切替などで消えた場合も、トグル式Voiceと押している間だけ録音するPTTの所有状態を解放します。

停止操作が失敗した場合は、Deck側の音声状態と押下所有状態を安全側へ戻してエラーを通知します。停止失敗後に`Listening…`へ固着し、ダイヤル全体が操作不能になる状態を防ぎます。

## Codexから返る結果を厳密に区別

音声操作の結果は、Codex側から返る次のトークンを厳密に解釈します。

- `start-confirmed`: 新しく開始できた状態
- `already-active`: Codexですでに録音中だったため、Deckを録音中へ同期した状態
- `pressed`: 停止または送信ボタンを実際に押した状態
- `already-idle`: Codexがすでに待機中で、送信操作を行っていない状態

`already-active`は`started`ではなく`synced`、`already-idle`は`sent`ではなく待機状態として扱います。何も送信していないのに送信成功として扱うことはありません。未知の結果や空の結果は成功にせずエラーにします。

## 通常のコマンドパレット操作を一時停止

Fast、Plan、Fork、Skills、Reviewなど、通常のCmd+Kコマンドパレットに依存する追加操作は、選択対象を安全に確認できるまで一時的にfail-closedとします。コマンドパレットが開いているかを誤認した場合でも、チャット入力欄へ検索文字列やReturnを送らないよう、操作せずエラーで終了します。

Agentキー、承認・却下、設定ダイヤル、音声入力、明示的なカスタムショートカットは、この一時停止の対象ではありません。

## マイクレベル表示は音声入力本体と分離

同梱のローカルヘルパーが取得するマイクレベルは、4画面を横断する波形表示の補助だけに使用します。音声データは保存も外部送信もしません。

ヘルパーのマイク許可が拒否された場合やレベルを取得できない場合は、静かな補助アニメーションへ切り替わります。Codex自身の録音、文字起こし、挿入、送信には影響しません。

## 実機で確認する項目

Codexの表示言語、メニュー構成、アクセシビリティツリーはアプリ更新や画面状態によって変わる可能性があります。更新後は、実機のStream Deck +とCodexデスクトップアプリを使い、少なくとも次を確認してください。

1. 待機中の1回目の押下でCodexの録音UIとDeckの`Listening…`が両方表示される
2. 2回目の押下で文字起こしが送信され、Deckが待機表示へ戻る
3. 素早い連打で複数回の開始・送信が発生しない
4. 録音中のキー、ダイヤル回転、タッチ操作が誤送信や設定変更を起こさない
5. 日本語UIと英語UI、複数ウインドウ、プラグイン再起動を含む状態で表示と実際の録音状態が一致する

これらの実機E2E確認は、ビルド・インストール後に別途行う必要があります。
