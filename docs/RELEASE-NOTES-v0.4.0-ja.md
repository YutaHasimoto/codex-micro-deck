# Codex Micro Deck v0.4.0 リリースノート

リリース日: 2026年7月23日

v0.4.0は、承認機能とダイヤル反映の仕組みを根本から作り直したリリースです。プラグインはCodexデスクトップの常設IPC接続（フォロワー接続）を持ち、承認待ちの検出も承認の送信も、キーボード入力ではなくCodexの正規のIPCメソッドで行います。

## 承認・却下キーの作り直し

これまでのバージョンには、直せない設計上の問題が2つありました。

1. 承認待ち（アンバー）の検出をrolloutログファイルから行っていましたが、Codexデスクトップは承認要求をrolloutファイルへ一切記録しないため、アンバー状態は原理的に検出できませんでした。チェック／バツを押すと必ず「⚠」になったのはこのためです。
2. 承認の実行がEnter／Escapeキーの送信だったため、フォーカス次第で誤送信の危険がありました。

v0.4.0では次のように動きます。

- プラグインはCodexデスクトップのIPCストリームを購読し、承認要求（コマンド実行・ファイル変更・質問など）を**リアルタイムで**検出します。検出中のAgentキーはアンバーになります。
- チェック（承認）とバツ（却下）は、Codexの正規IPCメソッドで該当の承認要求へ直接応答します。**キーボード入力は送信しません。**Enterが送信キーと衝突する問題は根本的に消滅しました。
- 承認待ちのタスクが**1件だけなら、Agentキーを選ばなくてもそのまま承認・却下できます。**複数ある場合のみ、対象のAgentキーを先に選びます。
- コマンド実行とファイル変更の承認はDeckから直接応答できます。質問（テキスト入力や選択肢）はアンバー表示のみで、Codex側で回答してください。

## ダイヤル反映先の解決を常設接続に変更

v0.3.2の「適用時に50ミリ秒だけ様子を見る」方式をやめ、常設のフォロワー接続でCodexが現在表示しているタスクを常時把握します。

- Codexが1件のタスクを表示中なら、そのタスクへ反映します。
- 空の新規タブが並んでいる場合でも、実在するタスクを状態データベースと突き合わせて自動で特定します。
- それでも対象を1つに絞れない場合だけ「⚠ Select」になります。Agentキーで選んでから再適用してください。
- Codexデスクトップが起動していない間は、従来どおり新規タスクの既定値（`~/.codex/config.toml`）だけを保存します。

ログも実態に合わせました。ライブ反映に成功すると「applied to the current Codex task (next turn)」、既定値保存のみの場合は「saved as new-task default only (no live target)」と記録され、以前のように両者が同じ「apply confirmed」になることはありません。

## Agentキー選択の永続化

Agentキーで選んだタスクはグローバル設定へ保存され、プラグインやStream Deckの再起動後も選択状態が復元されます。

## 重要な注意: 承認ポリシーがNeverのままだと承認は発生しません

`~/.codex/config.toml` の `approval_policy` が `"never"` の場合、Codexはすべて自動承認するため、承認要求そのものが発生せず、チェック／バツを試すことができません。Approvalダイヤルのタッチ領域を**長押し**すると既定値（Ask＝必要なときに確認）へ戻せます。既存タスクの承認レベルも、タスクを開いた状態でApprovalダイヤルから変更できます。

## 動作確認手順

1. Codexデスクトップを起動します。プラグインログに `[follower] connected to Codex Desktop IPC` が記録されます。
2. Approvalダイヤルで対象タスクの承認レベルをAskまたはStrictにします。
3. コマンド実行を伴うタスクを開始し、承認要求が出るのを待ちます。該当Agentキーがアンバーになります。
4. チェックで承認、バツで却下します。承認待ちが1件ならAgentキーの選択は不要です。
5. ダイヤル反映は、Model／Reasoning／Speedを回して350ミリ秒待つと「✓ Applied / Current task · next turn」が表示され、次のターンから反映されます。

全体の操作は[かんたん操作ガイド](../GUIDE-ja.md)、設定値と機能の対応は[機能対応表](CAPABILITY-MAP-ja.md)を参照してください。
